03 How a check works

  1. Submit. Any account can ask the contract to check a wallet against a registered airdrop.
  2. Fetch. The leader fetches the project's own eligibility source; every validator fetches it again and derives the same signals - wallet found or not, amount, source root, status code.
  3. Agree. The verdict is written only when validators agree exactly on all nine compared signals. A claim page on another domain can never produce ELIGIBLE, because only the registered source is ever fetched.

The verdict is a deterministic lookup, not a model opinion. The same wallet checked twice gives the same verdict, and any reviewer can re-derive it from the stored evidence. The TAC demo pins its verdict to the on-chain Merkle root of the allocation list. Source and tests · GenLayer docs: docs.genlayer.com.
